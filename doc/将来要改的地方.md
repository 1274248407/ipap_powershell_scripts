## make it right
改进架构，跑静态检查工具
角色定位：请你担任一名资深的 Windows 脚本重构专家。你推崇“极简主义”编码风格，主张通过集成高性能的第三方二进制工具（.exe）或成熟的 PowerShell/.NET 库来替代冗长、复杂的自定义脚本逻辑，以实现代码量的极致压缩。
任务背景：我正在 Windows 10 环境下开发一个 PowerShell 7 项目。目前项目中存在大量自行实现的业务逻辑，我希望通过“重构”来消除这些自行造轮子的代码，改用更专业、更稳定的外部工具或库。
任务描述：请利用 Trae 的代码库索引能力，深度扫描当前工作区中的所有 PowerShell 文件。识别出那些逻辑臃肿、代码量大、或实现了通用功能的函数与脚本块，并建议使用现成的二进制 CLI 工具（.exe）或成熟的 PowerShell 模块/库进行替代。
具体审计标准：
重点识别区域：复杂数据解析（JSON/XML/YAML）、文件系统高级操作（同步/比较/搜索）、大文件压缩/加密、网络协议交互、以及复杂的交互式文本处理逻辑。
重构约束：
多样化方案：可以推荐跨平台二进制工具（如 jq.exe, fd.exe, 7z.exe）或成熟库（如 ImportExcel, RestSharp）。
手动管理兼容：所有外部依赖将由我手动下载并存放在项目根目录的 bin/ 文件夹下。
相对路径引用：在示例代码中，必须使用基于 $PSScriptRoot\bin\... 的相对路径来调用外部工具，严禁使用绝对路径或依赖系统环境变量。
零代码开发：严禁建议任何需要编写 C# 源代码、自建编译 DLL 或配置复杂 SDK 开发环境的方案。
输出要求（逐项列出）：
代码定位：指明建议重构的文件名、具体函数名及现有逻辑摘要。
推荐方案：给出具体的外部工具/库名称及其官方获取地址。
重构收益：对比现有代码复杂度，预估重构后可减少的代码行数或逻辑比例。
重构示例：展示如何在 PS7 中使用 $PSScriptRoot\bin\ 引用并调用该工具，需包含基础的错误状态检查（如对 $LASTEXITCODE 的判定）。
输出格式：请以“项目全量瘦身审计报告”为题进行回复。首先提供一份“核心重构路线图”总结，随后按“代码削减收益”由高到低详细展开各项重构建议。
