[ ] 拆分 Get-ProjectBriefInfo：将格式化拼接（纯逻辑）与交互输入（副作用）解耦
  - 现状：Read-Host / Read-MultiLineInput 交互与 $tpl 模板拼装耦合于同一函数，交互 IO 无法脱离控制台测试
    （方法论：纯函数与副作用函数应拆解，副作用会传染；Get-ImageInfo/Get-NaturalSortKey 单测已先例）
  - 方案：提取纯格式化函数（内部函数或 Format-ProjectBrief），入参为已规范化的 5 个值，
    返回 ($formatted, $projectName) 双元组；Get-ProjectBriefInfo 仅负责空值判定 + 交互获取 + Trim
  - 纯函数可脱离控制台构造人造输入做 L5 全量断言；Get-ProjectBriefInfo 保留 Mock 交互侧测试

[ ] 拆分 Invoke-ParallelUpscale：并行块内纯逻辑与副作用解耦，使成功路径可测
  - 现状：ForEach-Object -Parallel 子 runspace 内（& exe 调用、Test-Path 输出文件判断、
    codecMap 映射、args 组装）与聚合计数（SuccessCount++/FailedCount++）耦合于同一函数；
    Pester 无法 Mock ForEach-Object -Parallel（无 filter Mock 会连聚合链一并吞掉，
    有 filter Mock 返回值不流入下游真实聚合，探针实证），成功路径因依赖真实 exe 执行
    与真实输出文件而无法在单元测试构造，单测只能覆盖失败路径计数与参数/异常契约
  - 方案：提取纯函数（内部函数或 Format-RealCuganArgs / Get-FfmpegCodec 等）：
    入参为图片对象 + 引擎参数，返回结构化结果（成功/失败标记），将 & exe 副作用
    隔离到唯一副作用点；聚合计数与结果分组独立成纯逻辑（参考 Get-ProjectBriefInfo 拆分模式）
  - 纯函数可脱离并行 runspace 构造人造输入做 L5 全量断言；Invoke-ParallelUpscale
    保留稀疏副作用（目录创建、exe 调用、日志）与失败路径测试
  - 附带发现：FFmpeg 分支对 Get-FfmpegPath 存在双调用冗余
    （67-70 行引擎解析 + 144 行 else 分支内再次调用），拆分时一并收敛；
    MaxWorkers 默认值 0 与 ValidateRange(1, 32)/文档"默认 8"冲突已于 2026-10-04 修复为 8
[ ] 全项目盘点纯函数与副作用函数：按方法论拆解，把可测试的纯逻辑从含 IO/交互/网络副作用的
