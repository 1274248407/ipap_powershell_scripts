# 分类与排序规则

- **make it work（做出来）**：让功能正确可用并交付上线——功能条目、发布准入、上线验收都在本段。
- **make it right（做对）**：不改用户可见行为的内部改善——结构、测试、文档、工具链、语法。
  反向判定：改用户可见行为的条目属 work，写错段的应移入。
- **make it fast（做快）**：性能。启动条件：真实工作流出现明确性能不满，或打包发布前基准超过
  约定阈值，才开本段；否则不做。
- **判定口径**：重要 = 直接贡献交付/结构/性能目标，不做会拖慢或损害目标；紧急 = 有外部时限，
  或正在阻塞其他任务。
- **排序**：段优先——先清空 work 段，再动 right 段（fast 看启动条件）；四象限只决定段内先后；
  出现真实外部时限或阻塞的条目可跨段提前。
- **象限处置**：重要且紧急 = 优先搞定；重要但不紧急 = 拆分任务、按章执行；
  紧急但不重要 = 集中时段快速搞定；不重要不紧急 = 自己看着办。
- **work 段完成线（上线验收）**：打包方案定稿 + 在 1 个真实漫画项目上端到端跑通 + 合并 main；
  「有人用」= 作者本人实际使用。
